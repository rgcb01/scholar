# Design Principles

- Minecraft is the laboratory, not simply a front-end for a traditional simulator.
- The system should not solve exercises automatically for the student.
- Tools should only do what a reasonable real-world equivalent could do.
- Complexity should come from meaningful systems, not artificial grind.
- Scholar represents knowledge but does not judge whether that knowledge is correct.
- Scholar and the future Physics/STEM Lab are separate projects.
- Scholar should be extensible by other mods and disciplines.
- Scientific readability has priority over mandatory pixel-art styling.
- The game should feel like Minecraft, while the document surface prioritizes learning and reading.
- Prefer carefully designed subsets over implementing huge technologies for completeness.
- Develop incrementally and keep the project functional.
- New features should answer: does this make the system more useful or richer, or does it only make it more complicated?
